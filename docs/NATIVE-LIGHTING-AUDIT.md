## 原生环境光入口

精确原始全屏 PS 的 b2 反射给出数量字段、SH、颜色、衰减、区域逆矩阵和插值范围；指令确实以每条 12 个 float4（192 字节）索引区域，并以 t10 位置候选和仿射矩阵执行区域判断。三帧 b2 起始 uint 数量字段依次为 **4、4、1**，与室内/切换场景的条件一起保留为候选证据。反射里的数组上限为 64，声明大小为 12,352 字节；实际分配是 16,384 字节，不能把分配尾部变化当有效区域参数变化。

网格 PS 读取 b6 的十个 float4（160 个有效字节），法线参与方向求值，v6.z 参与衰减。实际分配 256 字节，不能把尾部 padding 的变化当光照变化。输入的生成粒度、区域预混合方式及玩家对象关联仍未确认；原版存在法线/位置相关光照逻辑，不能称为整个人统一亮度。

镜头对照时首个网格绘制从 3687 索引与一份 VS，变为 2652 索引与另一份 VS。这可能包含不同对象或不同几何分支，当前证据不能区分。两份 VS 的常量槽布局不同，固定采 VS b0/b2 不能自动解释为相机。PS 相机按精确原版身份和反射偏移取得，但世界参考仍需独立位置/像素/深度检查。

## 数据缺口与下一项有界任务

首版缺口是 BGRA8 法线读回、反射 cube-array、D24 深度的明确解码/对应、网格 VS 输入语义与玩家对象关联、原生局部灯生产者及更新路径。普通 capture bytes 变化不能补齐这些语义。

23:04 更新：r2 已取得一次有效实机快照，两路径 BGRA8 原始位读回和 SHA 通过；固定候选矩阵与位置/深度在存储误差边界下数值相容。生产者与位置独立性未知，不能据此认定完整坐标对应已验证。见 [r2 实机摘要](validation/native-live-r2-bgra-2026-10-08.json)。下一项补证以**全屏材质位置/法线的上一写入 shader 和输入链**为范围：确认直接几何输出或深度重建，再审计区域参数的坐标与生产者；玩家网格输入先按实际 VS 身份定位，不追加未关联对象的盲目走动采集。原生局部灯参数和更多材质另行记录缺口，避免扩大为全帧通用采集平台。

## 成本与恢复

三次 copy enqueue 的 CPU 时间为 4.53 / 3.24 / 4.73 ms，读回加文件 I/O 为 84.47 / 90.93 / 89.86 ms，分别跨 2 / 2 / 3 次 Present 完成。这些是触发采集成本，含摘要/磁盘处理，不能作日常 idle、正式效果 GPU 时间或帧时间分布。没有补填 FPS、帧时间 CSV 或长期稳定性。

每次采完发送 stop，最后采集助手也已退出。没有在游戏运行中替换 DLL。r10 完整备份保留，停机恢复步骤仍有效；输出目录与三个配置/日志文件的最小权限处理未改变 game 目录 ACL。新插件仍为只读诊断，未迁移色调或新增光照。
