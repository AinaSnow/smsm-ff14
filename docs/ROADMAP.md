# 新版 FF14 可选画质改进路线

2026-10-08 用户批准。目标是逐项证明画质收益和成本，不机械复刻旧 SMSM 的所有效果。

## 当前开发优先级（用户追加授权）

“不明显”不等于无效。景深和反射实验保留并继续研究，执行证据、画质收益和性能成本分别记录；暂停的是重复、无明确判据的肉眼找差异，不是研究本身。

当前优先开发单盏可控动态灯。首轮已完成资源/坐标接口审计、实际 D3D11 WARP 绘制与浮点读回工具、单灯数学原型和两份主光照字节码的注入候选，详见 [SINGLE-LIGHT.md](SINGLE-LIGHT.md)。84 项像素/差分检查及 4 项包管理检查通过。离线支持逐帧更新位置；游戏候选目前使用静态烘焙参数加 F10 文件重载，尚无游戏内连续交互控制器，且默认关闭。

第二轮新增 213 项实际混合/材质分支检查与 48 项独立屏幕空间遮挡检查，全部通过预设判据，同时明确记录边缘误差和缺失深度的漏光。已有抓帧显示两个主光照变体各绘制一次但写入不同目标，不能直接推断每像素是否重复叠加；下游合成、实际混合状态仍待确认。遮挡只在离线工具中启用，没有新游戏包或客户端写入；不以通过合成测试代替材质适配、实机表现和成本验证。

后续顺序：

第三轮追加证据：下游资源已追踪到不同材质/合成路径及同一场景目标。局部平面复核使六组几何误判减少约 61%，运动变化误差略增，仍默认关闭。新增真实 R11G11B10 写入测试发现候选小幅白灯增量可能消失或出现通道不等的量化；下一步先审计材质合成中开方/曝光前的注入，不盲目提高强度或直接叠最终颜色。详见 [第三轮记录](LIGHT-INJECTION-AND-PRECISION.md)。

1. 确认游戏实际阶段、混合状态和每像素注入次数，再做少量有明确判据的单灯测试；不预先保证两份变体覆盖所有画质设置。
2. 遮挡与材质适配：不把屏幕深度当完整场景几何，明确穿墙、屏幕外/背面信息及透明材质限制；白衣和肤色优先保持自然。
3. 多灯摄影预设：逐盏隔离、总能量限制及实际成本测量，再考虑保存摄影配置。
4. SSGI 间接光照：独立研究深度厚度假设、离屏缺失、时域噪声和能量守恒。完整硬件光追另做 API、几何/加速结构及注入可行性研究，不把屏幕空间效果称为完整光追。

风格化方向并行保留在研究列表：柔和漫反射、冷暖阴影、卡通明暗分层、克制轮廓光、细描边、材质高光。每项独立开关、默认关闭；先用灰阶、白布和肤色参考检查明度/色相/边缘，再进入游戏。第一轮未实现这些风格化效果，不用简单全局染色替代材质光照。

所有新包保持不可变、可备份和独立选择。不热换 DLL，不复用 r5 动态参数方案。本地开发并提交，不推送发布、不使用子代理。

## 基线与状态

固定 50% SMSM 色调混合，保留游戏 Bloom 和游戏景深。用户接受了指定场景中的色调和辉光；r9 是收敛基线，不是全面验证的稳定版。r5 无响应根因未明，动态色调切换继续停用。

| 效果 | 已有证据 | 未完成 | 新管理包默认 |
|---|---|---|---|
| 色调 | 50% 外观获接受；编译端点检查；r10 重载及传送、室内外、短战斗未报告问题 | 更广泛场景、长时间稳定性和帧时间 | 开 |
| Bloom | 恢复游戏实现后用户确认光晕正常 | 其他光照组合 | 游戏原版 |
| 反射 | 诊断确认路径及雨天贡献；普通扰动肉眼不明显 | 继续离线研究边缘、过滤和运动稳定性；画质与成本分别验证 | 关，保留实验 |
| 法线阴影 | 历史主光照路径定位、局部 ASM 插入检查 | 当前替换执行、遮挡/漏光/运动表现、成本 | 关，实验 |
| 抖动 | 编译/接口检查、输出阶段标记的历史日志 | 当前执行、色带收益、噪点与帧时间 | 关，实验 |
| 径向模糊 | 更新视口接口、历史路径定位 | 特效触发、运动画面及成本 | 关，实验 |
| 景深 | 原实验保留；新增当前近远两级合成的 264 帧真实离线绘制检查 | CoC、散景核、完整焦点过渡、边缘漏色与成本 | 游戏原版，实验继续研究 |

2026-10-08 反射隔离对照：用户在湿石板路场景报告看不出区别，并提供单张截图。只读检查确认 r10 完整性通过、仅选择 `reflection`；当前 calls/debug 日志关闭，无运行日志可证明替换执行。截图中的亮斑不足以证明目标 SSR 路径参与。结果为不确定，不能据此认定没有执行或已经改善。代码当前只对最终反射颜色采样施加每轴最多三个源纹素的扰动，保留原有追踪、命中、遮罩与衰减，并非新增反射算法。停止要求用户盲目换地图或调大强度；下一步先建立可逆的执行诊断，再决定是否继续画质对照。实验仍默认关闭。

后续执行诊断已构建并得到正向反馈：独立包 `diagnostic-2026.09.15-reflection-marker` 在原始反射 shader 的唯一返回之前增加一条固定紫红色 RGBA 输出指令。用户截图显示标记，报告按住 F9 后消失、少量残留在转动视角后消失。确认目标替换输出在该场景可见；残留来源尚未确定。原 r10 与诊断包均保持不可变，不改变 DLL/INI/头文件。第二包 `diagnostic-2026.09.15-reflection-contribution` 保留原版权重与 alpha，只改变反射颜色采样输入。用户随后提供雨天湿路面局部紫色倒影截图，报告只有下雨天看得出；确认标记在此条件下通过了原有权重，不推断其他场景也仅雨天有效。两个诊断均有正向结果，下一步为当前雨天场景的 r10 普通反射隔离画质对照。具体判据及恢复命令见 [REFLECTION-DIAGNOSTIC.md](REFLECTION-DIAGNOSTIC.md)。强制颜色只用于诊断，不代表真实反射质量、范围或强度。

默认只开启有当前场景接受反馈的色调。不将阴影/反射“存在于资源包中”或成功编译当作已经生效。`r9-baseline` 预设保留 r9 的完整组合，供复现，名称不代表稳定性认证。`daily` 是保守功能选择，尚不能称为经过测量的低开销预设。

反射本轮结论（2026-10-08）：在两个诊断取得正向结果后，用户恢复 r10 普通反射隔离，仍报告“去掉紫色我是看不出区别来”。只读检查确认 r10 清单完整性及反射隔离选择。当前采样扰动没有展示可辨认的画质收益，保持实验默认关闭，停止要求用户重复找场景或单纯增加扰动幅度。该结论只适用于已测试场景，不代表数学输出完全相同或没有性能开销。后续若重做反射，先以离线基准证明具体问题与改进，再安排实机复核。

## 第一阶段：稳定与诊断记录

2026-10-08 实机反馈：用户按色调关闭/恢复与 F10 重载步骤测试后，报告“有变化没卡顿跟错误”。随后对传送、室内外与短战斗检查回复“看都没有问题”。两次只读检查均确认 r10 清单完整性通过，磁盘仅选择 `tone`。本轮基本观察通过；具体地点、实际时长与 FPS 未提供，未据此补填。三个场景分别记录于 `artifacts/validation`，来源为同一次汇总反馈。尚无帧时间数据，也不代表其他效果或长期稳定性通过。下一项为反射隔离对照。

锁定颜色比例、显示器/HDR、分辨率、抗锯齿、升频、帧率限制和游戏亮度。记录包清单 SHA-256、请求开启的效果与重载状态。

游戏内只做一次约 10–15 分钟的基本检查：

1. 在已用过的室内与室外间切换，完成两次传送，检查人物颜色、光晕、黑屏/闪烁和异常停顿。
2. 完成一段 2–3 分钟的普通战斗，检查 UI、技能特效、卡顿和无响应。
3. 记录场景、设置、结果与大致 FPS 范围；如果发生异常，记录触发动作和时间，停止追加效果。此轮不做 F8 抓帧，不要求重复景深截图。

验收：结果是“这些场景的基本检查通过/失败/不确定”，不是全面稳定。FPS 范围只作粗略观察。帧时间对照使用相同采样工具和列定义的毫秒 CSV；保留卡顿离群值，不将帧间隔当作 shader GPU 时间。每种状态至少两次、每次 30–60 秒，先预热并保持镜头、天气、动作及限帧条件一致；接近帧率上限时不能以 FPS 不变推断无成本。

`tools/record_validation.py` 只记录观察和汇总传入数据，不自动测量或判定成功。JSON 中始终区分文件选择、人工观察与 shader 执行证据。

## 第二阶段：独立效果和单项对照

首轮实现：`tools/build_preview.py --managed` 生成不可变的功能库；`tools/manage_preview.py` 根据选择部署独立 shader 文件及状态清单。色调、反射、阴影、抖动、径向模糊分别可开关，`--isolate` 只保留一个效果，`vanilla` 关闭所有替换。

新建包只收录已有接口审核和编译检查的 shader；profile 开关不会自动寻找相似 hash，也不会写入新算法。原始安装包不修改。默认游戏退出时操作；`select --live` 是明确的 shader 文件变更模式，不写 DLL、头文件或 d3dx.ini。完成文件变更后需手工按一次 F10；工具不会发送按键，也不会声称游戏已应用。F9 临时绕过所有当前替换，隔离模式下才是只对照该效果。

核对依据是当前使用的官方 [3DMigoto 1.3.11 Hunting.cpp](https://github.com/bo3b/3Dmigoto/blob/1.3.11/DirectX11/Hunting.cpp)：`ReloadFixes` 扫描替换 TXT，`ReloadShader` 重新编译，`RevertMissingShaders` 将未找到的替换指回原版。因此必须同时管理 TXT 和 BIN；不能仅删除 BIN 或把其他合法 shader 名放在同一目录。重新启用时创建新的文件时间戳，以触发重新编译。

源码审核不等于 FF14 实机验证。第一次只用已知可见的色调做“关闭 → F10 → 开启 → F10”循环；不得顺手开启其他实验。若出现重载错误或无响应，停止热切换，退出后恢复备份/重启，并保留日志。只有该循环成功后，再验证其他效果的启停；未确认前状态始终为 `pending-restart-or-F10`。旧 r5 的 t120.y/F6/F7 方案不复用；现有输出抖动的 t120.x 阶段门控仍保留并列为待验证。

## 第三阶段：证明执行、画质和成本

每项分别满足三个条件才考虑默认启用：

1. **执行**：在当前客户端、画质与场景上证明替换输出实际进入结果。可使用独立、可逆、明确标记的诊断输出或受控 GPU 证据；hash 存在、旧抓帧命中、文件安装正确不能替代它。
2. **画质**：同机位只切换该效果，观察预先定义的问题。反射检查边缘、断裂、闪烁和运动；阴影检查接触细节、错误变暗和漏光；抖动检查灰阶/天空色带与额外噪点。F9 带来的其他效果差异不得归因给被测功能。
3. **成本**：可重复的帧时间对照，报告样本数、中位数、P95/P99和异常。无法测量、受限帧/场景变化干扰则标为不确定。不得把增加采样数直接换算为帧率损失或声称零成本。

没有明确收益的功能保持实验、默认关闭。摄影预设要等高成本效果证明收益后再定义，不先建立一个全开的“高质量”名目。

## 第四阶段：景深研究

首轮实际渲染工具已用于原始合成 shader `4b85fee6dc176fb3`：恒色/非单位曝光、不同近远层颜色、近层零覆盖边界、全黑输入共 264 帧，验证两级近远层合成、权重过渡和平方/开方能量域；结果与独立公式一致。见 `tools/validate_dof_composite.py` 与 `artifacts/dof-composite-validation-v1/report.json`。这不是完整景深验证：尚未复现深度到 CoC 的生成、散景核、前景扩张与整链边缘漏色，不能凭合成测试宣布散景移植完成。

暂不要求用户继续截图。先确认当前路径实际执行，再梳理 CoC 编码、近远层、两个模糊级别、动态视口和最终合成的能量域。

离线已知输入至少包含：单点光源（模糊核形状/半径）、恒定颜色（能量守恒）、前景遮挡远处光源（边界/漏色）、焦点平面变化和不同长宽比。以当前游戏原始字节码作参考，区分源码转写误差与算法变化。保留输入、参数、输出和统计；离线证明不能替代实际命中和游戏测试。当前 ±10° 48-tap 实验不视为旧 SMSM 完整散景移植。

## 第五阶段：维护、升级与回退

本轮实现版本拦截、不可变包完整性、清单所有权、自动备份、一次升级、回退、异常中断恢复和提取清单审计。`audit` 只报告新提取结果与旧 original SHA 是否匹配，不启用 shader，也不将匹配等同于执行。

后续完善：更细的画质/升频兼容矩阵、可证明成本的日常/摄影预设、自动化离线渲染测试及经过实机验证的重载流程。推送、发布与旧包清理不属于本轮授权。
