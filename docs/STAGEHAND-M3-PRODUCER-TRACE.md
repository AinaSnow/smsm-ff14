# M3 上游追踪候选：生成光照纹理的绘制与常量

前两轮实采已确认当前裙装读取的 t0/t1 随原生灯颜色变化。此轮继续追踪生成这两张纹理的绘制和灯参数；性能工作按用户要求暂缓。

## 已有静态线索

旧抓帧曾把 `e9f57e0834b642f5` 和 `8b384acd7a03c836` 的 o0/o1 关联到后续材质光照输入。本轮重新核对提取清单、原始 DXBC 摘要并反汇编，确认两者都有 b2 `g_LightParam`：位置字段偏移 0、漫反射颜色 32、高光颜色 48、衰减参数 64，结构反射大小 392 字节。不能将这两个历史 shader 直接认定为当前 Stagehand 灯入口。

## 新增定点记录

现有 `probe` 命令保持兼容，0.2.1 桥不需要更新。probe 在下一帧临时开启既有资源写入追踪，在帧末关闭；结束、取消和错误路径均停用。采样仍是 OFF/暖/冷/OFF，不开启 r8 或 marker。

收集 immediate context 中同时向 o0/o1 两个 R11G11B10_FLOAT 目标写 RGB 的候选绘制。只复制其 PS b0–b6 常量，记录当时绑定范围、帧/绘制号、PS/VS 身份、输出资源 ID/代次及视图/混合信息。最多 128 个候选、32 MiB 常量；输入、输出和候选常量共享原有 256 MiB 总预算。达到上限显式标记截断，不把残缺列表当完整来源。

裙装 t0–t3 快照携带同次捕获的资源历史，包括最后观察到的写入、写入者身份、同帧/同启用周期范围和已有一层复制引用。分析只把同帧、早于消费者、同资源且同生命周期代次的候选关联起来。过往帧与新启用周期不能混用；没有捕获到最后写入者或出现截断时保留缺口。

同时补录消费者 sampler0，供后续验证屏幕 UV 采样条件。常量始终在候选绘制前通过同一 GPU 命令流冻结，即使底层缓冲在下一次绘制前被改写，已保存数据保持原值。

`tools/analyze_light_producer_probe.py` 先核对全部原始字节，再按实际 PS 摘要从客户端提取清单定位反射布局。仅在匹配的 CB 绑定范围内解读字段。位置、颜色、资源身份等原始输出只留本地；坐标系、强度缩放、Stagehand 灯身份需用真实四态控制参数继续验证。

## 验证与待验收项

- WARP 实际绘制：520 次无颜色目标绘制不占候选名额；生产者输出与消费者输入按同帧资源对应，生产者 CB 快照保留改写前的值。
- 第二帧没有新生产者时，旧记录明确为历史观察，不通过当前来源关联；129 次候选只保存 128 条并标记截断。帧末和取消均关闭追踪。
- 官方 ReShade 6.8.0 硬件运行时检查通过：原始输入字节保持一致、原输出误差约 `2.98e-8`、关闭恢复误差为零，sampler point/clamp 与 trace 字段正确。该硬件合成场景没有双 R11 生产者，正向生产者关联由上述 WARP 场景验证，不能混称实机游戏已通过。
- 原输入采集模块 → 新候选的升级、中断恢复、设置/运行库保留和 r10 恢复模拟通过。新候选默认关闭，完整 M3 仍未通过。

候选过滤可能遗漏其他格式、单目标或其他输出槽的路径。RTV 绑定只证明写入意图，混合、模板、局部覆盖与成功像素写入仍要另核对；compute/UAV/间接绘制和完整复制图仍有缺口。实际采集后先确认当前 t0/t1 的写入者是否被捕获，再用颜色/位置等参数进行对应，不以字段名称或命中次数验收。

用户随后正常退出游戏，并允许 Windows UAC 后，已完成原生 add-on 更新。安装摘要和 producer-trace 能力凭据核对通过，旧模块完整备份已核验，ReShade runtime/设置保留；0.2.1 测试桥、r10 冻结包不变。无待执行命令或所属测试灯，新启动不会自动开始采集。
