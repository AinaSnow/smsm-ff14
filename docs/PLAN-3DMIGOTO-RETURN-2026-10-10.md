# SMSM 开发计划：回归 3DMigoto

日期：2026-10-10  
状态：R0 已完成；R1 已复现崩溃并部署用户接受的配置规避候选，实机验收待完成。R2/R3 未通过。详见 [执行记录](3DMIGOTO-COMPATIBILITY.md)。

## 方向决定

开发主线切回 **3DMigoto 游戏原生 shader 替换**，目标重新聚焦于实际可见、可独立开关的画质改进。ReShade 原生采集、Stagehand 测试桥及相关灯光研究支线冻结归档，暂不继续开发或部署。

原生灯能够影响人物受光，已有实机观察和参数关联证据。此项调查收口，不再要求穷尽灯光入口、每个材质变体或所有微小像素差，才能继续画质开发。新增手工灯也不作为改善地图原有光照的验收替代。

后续执行以本文的新优先级为准。原 `ROADMAP.md`、`NATIVE-LIGHTING-PLAN.md`、`STAGEHAND-NATIVE-LIGHTING-PLAN.md` 中的灯光研究待办保留为历史，不自动延续为当前任务。

## 基线与边界

| 项目 | 决定 |
|---|---|
| 开发后端 | 3DMigoto |
| 画质恢复基线 | 已发布 r10：已接受的固定 50% 色调；其他实验保持独立、默认关闭 |
| 旧运行库对照 | 项目原有 3DMigoto 1.3.11，仅作兼容对照和回退依据 |
| 首选兼容候选 | 官方 3DMigoto 1.3.16；实测通过后才成为新的运行库基线 |
| Dalamud | 必须兼容正常 UI 操作；测试时记录并固定实际版本 |
| ReShade 支线 | 归档冻结，保留源码、工具、证据和恢复资料，暂不参与新主线 |
| r10 发布物 | 标签、原包和校验值保持不变；新运行库组合另建候选包 |

这里的“开发基线切回”不表示客户端 DLL 已完成替换。仓库方向调整、历史保存和游戏安装切换分别执行、分别记录。

本计划不包含新增灯光控制器、继续 SH 实验、扩大 GPU 采集框架、全材质覆盖或 ReShade 与 3DMigoto 并装兼容研究。Stagehand 本体作为用户独立插件保留；归档 SMSM 测试桥不等于卸载或改变用户的 Stagehand。

## R0：保存并冻结旧支线

目标：完整保留已有工作，让回归开发有明确起点。

1. 执行前重新核对工作区、当前分支、已发布 r10 和游戏安装凭据。当前工作区存在未提交的桥接校准改动，应先检查并保存，不能直接覆盖。
2. 将 ReShade/原生灯光支线保存为独立归档引用，例如 `archive/reshade-native-lighting-2026-10-10`。与该支线相关的未提交改动单独保存为归档提交或补丁，不混入新的兼容修复。
3. 在归档中保留原生 add-on、SMSM Stagehand 桥、采集/分析工具、验证文档及构建说明。正在准备的冷光校准等后续工作停止推进，按完成程度如实记录。
4. 原始画面、GPU 数据、世界位置、用户配置及安装备份继续保存在本地忽略目录，不上传 Git。记录其保留位置；不要直接移动仍被安装凭据或 Dalamud 开发插件路径引用的包目录。
5. 建立新的回归开发分支，例如 `feature/3dmigoto-dalamud-compat`，首选以 r10 标签为代码/效果起点。确有必要的管理修复逐项移植，并写明来源；ReShade 功能不作为新分支的默认构建或运行依赖。
6. 更新主线 README 和路线入口，使本文成为当前计划；旧灯光研究文档标记为归档，避免其“下一步”继续触发开发。

禁止用 `git reset --hard`、`git clean` 或清空目录处理未归档工作。若采用独立工作区完成回归，先保留原工作区，直到恢复路径和所需文件均核对完成。

**交付：**归档引用/补丁清单、新分支起点、r10 校验记录、客户端恢复方案。  
**通过条件：**能找到并恢复归档前的源码、未完成工作和客户端安装；r10 原发布物未改变。

## R1：解决 3DMigoto 与 Dalamud 点击崩溃

首要问题：启用 3DMigoto 与 Dalamud 后，点击 Dalamud 的 ImGui 界面导致游戏崩溃。

这与此前 SMSM 测试桥写 `status.json.tmp` 的初始化竞争是两个问题，不能用桥加载成功替代此次兼容验收。点击只是触发条件；在取得崩溃栈前，不认定一定是 ImGui、鼠标钩子或某个 DLL 的问题。

### 最小测试组合

| 组合 | 配置 | 用途 |
|---|---|---|
| A | Dalamud，无 3DMigoto、无 ReShade；临时关闭第三方插件 | 验证 Dalamud 自带窗口正常 |
| B | 3DMigoto 1.3.11＋Dalamud，关闭全部 SMSM shader 替换 | 隔离旧运行库冲突；已有可靠复现记录时可省略重复撞崩溃 |
| C | 官方 3DMigoto 1.3.16＋Dalamud，同样零替换 | 验证升级是否改善兼容 |
| D | 通过的运行库＋Dalamud＋r10 色调单项 | 确认兼容与实际 SMSM 效果能够共存 |

使用 Dalamud 自带设置/插件管理窗口，先排除具体第三方插件的 UI 代码。随后再恢复用户常用插件，确认实际使用组合。临时禁用不等于删除插件或清空配置。

固定游戏构建、Dalamud 版本、图形设置和其他注入环境；不要同时升级多个组件。ReShade 及其诊断 add-on 不加入这轮对照。不要直接覆盖官方默认 INI：官方 1.3.16 发布配置偏向 hunting/抓帧，兼容测试应关闭 hunting、自动导出和持续详细日志，保留必要的短时错误记录。

每个候选只做一轮明确的短检查：打开窗口、点击按钮、拖动窗口、输入文字和关闭重开。发生崩溃后保存对应 dump、日志、异常模块/偏移、DLL 校验值和复现动作，停止重复同一组合。

若 1.3.16 仍崩溃，先根据栈定位问题属于设备/上下文包装、交换链、绘制状态恢复、窗口输入链还是插件回调，再修改相关配置或代码。只有找到具体修复依据后，才引入固定提交的上游源码构建或维护分支；不轮流替换来历不明的 DLL。

官方 1.3.15/1.3.16 说明包含崩溃和注入兼容修复，因此值得优先验证；目前没有直接证据证明它已经修复本项目的 Dalamud 点击崩溃。升级是候选方案，不提前记为解决。

**交付：**兼容性记录、可复现崩溃资料或修复、固定运行库版本/来源/校验值。  
**通过条件：**零替换和 r10 色调单项下，Dalamud 核心窗口与用户常用 UI 操作均正常；关闭效果和回退正常。  
**停止条件：**未定位的崩溃仍存在时，不叠加新画质功能，也不重新开启灯光研究分散问题。

## R2：恢复 r10 可用效果与管理流程

1. 在游戏正常退出时，按安装凭据备份并撤下 ReShade 诊断环境，再部署经过 R1 验证的 3DMigoto 组合。保留 ReShade 设置和恢复资料；不清空用户游戏目录。
2. 初始只开启 r10 已接受的色调。游戏原版 Bloom 和景深先保留；反射、阴影、抖动等历史实验不批量开启。
3. 核对效果开关、shader 重载、升级和回退。运行库 DLL 的切换按停止游戏后的安装流程执行；shader 重载能力单独验收，不能推断 DLL 也可热替换。
4. 验证最少的一组日常操作：普通场景、一次切图、Dalamud UI 操作。已有有效记录可以复用；没有异常时不扩大测试矩阵。
5. 将“r10 效果＋新兼容运行库”发布为新的候选版本，说明实际改变的内容，不覆盖 r10 标签或声称所有旧功能已经适配。

**交付：**可回退的 3DMigoto 候选包、简明使用说明、已验证/未验证功能表。  
**通过条件：**用户能正常使用已接受的色调和 Dalamud，不依赖 Stagehand 测试桥或 ReShade 采集链。

## R3：回到单项画质开发

先选择一个用户确实关心、能明确指出不足的画面问题。一次只推进一个效果，不再把完整渲染系统调查作为前置项目。

| 方向 | 要解决的具体问题 | 验收重点 |
|---|---|---|
| 色调与高光 | 灰雾感、亮部细节丢失、肤色或场景颜色不合适 | 原版/r10/候选同场景对照，暗部和高光均保留层次 |
| 原生景深 | 焦点过渡、人物边缘、前景遮挡、散景外观 | 明确焦点场景和前景遮挡案例；比现有版本有可辨认改善 |
| 反射 | 台阶、噪点、边缘或粗糙度不自然 | 在确实有反射贡献的场景对照，避免只改参数却看不出收益 |
| 阴影与色带等 | 明确的漏光、缺少接触感或渐变断层 | 对应问题实际减轻，同时检查闪烁、轮廓和 UI 影响 |

摄影需求优先时可先选景深；日常观感优先时可先选色调/高光。该选择在 R1/R2 稳定后确定，不同时展开全部方向。

每项都应先写清“原画面的什么问题、预期改善什么”，再做最小实现与一至两个代表场景的开关对照。每轮交付都要说明看到了什么改善、有什么副作用、是否值得保留。若只是编译通过、命中计数增加或微小像素不同，仍不能算画质收益。

遇到具体异常时才启用针对性的抓帧和 GPU 分析。已有 ReShade 调查成果可作为历史参考；重新启用或扩建该支线必须另行决定，不默认恢复其待办。

## 工作节奏与验收原则

- 先兼容，再恢复已接受的效果，再开发新效果。
- 用户实机操作集中为短而明确的一轮；没有新假设时，不反复要求退出、重进或观察同一盏灯。
- 纯 Dalamud 插件改动优先采用已验证的禁用/更新/启用流程；本计划不以开发新的 Dalamud 工具为目标。
- 默认关闭未被接受的实验。当前不开展独立性能优化项目，但新增明显卡顿、崩溃或加载异常必须如实记录。
- 每个完成阶段提交独立代码和简明验证结论；诊断工具的完成不等同画质功能完成。
- 如 3DMigoto 兼容性无法在有证据的修复范围内解决，提交明确阻塞结论再决定后端，不自行恢复 ReShade 灯光支线。
