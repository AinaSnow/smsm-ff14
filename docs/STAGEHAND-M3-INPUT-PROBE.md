# M3 定点材质输入采集候选

M2 切图清理通过后，继续验证已知原生灯如何影响当前裙装。性能问题按用户要求暂不处理。此候选新增只读采集和有限控制流程，尚未完成实机数据关联。

## 固定入口与输入

已核对当前客户端原始 PS `e86f0d4916054deb` 的反射表：t0 为 `g_SamplerLightDiffuse`，t1 为 `g_SamplerLightSpecular`，t2/t3 为 GBuffer 输入；b0–b6 分别包含材质、公共、PBR、相机、实例、动态材质和环境参数。这些名称只能决定采集范围，不能证明 Stagehand 灯已经对应到其中某个资源。

新命令 `probe <PS hash> <elements> <VS SHA-256>` 在普通材质 roster 内匹配 PS，再按 VS、元素数及存在 RGB 写入目标过滤。当前桥固定到已经人工核对空间掩码的裙装几何，元素数 7914。没有颜色目标、RGB 写入掩码为零或几何条件不同的绘制不占名额；每帧最多两条匹配绘制，仍须从前后差分确认实际非零颜色贡献，不能只凭过滤命中验收。

同一个 immediate context、同一次原始绘制前，冻结 PS b0–b6 及 t0–t3；记录资源 ID、CB 绑定区间、SRV 格式/维度/子资源。CB 保存完整底层缓冲和绑定区间，单缓冲最多 4 MiB；纹理只支持 Texture2D 视图的实际首个绑定 mip，其他视图明确报告不支持。输入复制临时解除 predication 并恢复，原始 draw 保留其原有状态。原有 RTV 前/后/帧末和 Present 图像一并保留，输入与输出共享 256 MiB 总预算。

输入在 draw 前按 GPU 命令顺序冻结，帧末等完成事件后读回。资源持有到本次审计结束，避免同次采集指针复用。数据保存在本地，`analyze_native_output.py` 逐文件核对长度/摘要与总预算。绘制输出不被替换；r8 和 marker 在 probe 开始前关闭。

## 桥接流程

测试桥 0.2.0 增加手动 `probe`，序列为 OFF → WARM → COOL → OFF，灯参数与 M2 相同。每态等待两秒、最多等待采集 15 秒；最后一份 OFF 用于检验基线漂移。运行中移动或换场景仍停止，灯和队列清理规则保留，加载不自动运行。

桥先检查安装凭据是否具备 `material_input_probe`，拒绝旧 add-on；逐份检查模式、PS/VS/元素数、最多两条 draw、必要 b3/b6/t0/t1 输入及三份 RTV 图像是否完整。失败停止，不把残缺记录当成功。`run` 仍是已有三态 sample，`lifecycle` 仍是最多 60 秒无采集暖光。

## 已完成验证与边界

- 桥 Release 编译零警告，27 项离线检查通过，包含四态结束恢复、旧 add-on 拒绝、缺少输入/错误几何拒绝、消费后的 probe 中断清理。
- WARP 实际绘制确认：520 次无颜色目标绘制不耗名额，错误几何/零 RGB 写入跳过，最多两条快照；原 draw 回调次数与 CB 绑定区间保留，绘制后改写原 CB 不影响此前快照。
- 官方 ReShade 6.8.0 实际硬件运行时确认：采集到的支持类型输入逐字节等于已知输入；输出相对 WARP 原版误差约 `2.98e-8`，关闭恢复误差为零，ambient/marker 执行数为零。测试使用合成几何，不能替代游戏实测。
- 旧 r8 add-on 到候选的升级、中断恢复、用户设置保留和 r10 恢复模拟通过。游戏中的 r8 仍关闭，r10 发布包不变。

用户正常退出游戏后，已更新原生采集 add-on 和 0.2.0 桥登记。原生更新使用 Windows UAC 提升执行固定校验脚本；安装文件与候选摘要一致，ReShade runtime/用户设置、桥身份和 profiles 均保留，旧包与升级前文件已备份。无待执行命令或所属灯，r10 冻结包不变。安装成功不等于实机采集或 M3 通过。
