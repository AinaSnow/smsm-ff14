# r5：精确头发变体的可见覆盖诊断

此候选用于解释 r4 实机对照无明显差异。r4 精确目标已核实来自 `hair.shpk`，不是皮肤/衣服的通用入口；所属包有 200 个唯一 PS，仅命中一份不能证明覆盖当前玩家。

覆盖模式仍只匹配 `980154264a89fba1`。独立 marker 保留原 PS 的全部指令，仅把最后一次 RGB 输出替换成紫色 `(1,0,1)`。保留输入/输出签名、alpha、discard、原生深度取样拒绝和 early-depth 声明。桥只临时替换 PS，原绘制参数以及深度/模板、混合、颜色写入掩码、CB、SRV 都沿用游戏状态；正常返回及异常路径恢复原 PS。动态类实例、延迟 context 和 DrawAuto 不替换。

该标记不依赖原生区域复制或相机匹配，也不采样额外资源。它能将“目标材质是否绘制在这里”与“区域环境项是否有效/明显”分开；标记开启时环境光实验关闭。紫色是诊断颜色，不能解释为照明改善。被原生裁剪、深度/模板拒绝、遮挡、透明混合或后续绘制覆盖的像素仍可能不显色；因此未观察到紫色不等于该对象永远不用此 shader。

## 开关与一次短测试

仅在带 `coverage_shader_sha256` 的新候选中可用；控制工具会拒绝向 r4 发送不支持的命令。每次启动默认关闭。进入原来的固定场景并站稳后，由助手发送：

```powershell
python tools/request_native_ambient.py '<game 目录>' coverage
```

标记最多持续 10 秒，随后恢复原 PS 并在下一次 Present 更新状态文件。暂停渲染超过截止时间后恢复的首个绘制也不会继续显示标记。`off` 可提前关闭；`on`/`half` 会结束标记并进入对应实验模式。资源诊断、异常及 swapchain 销毁也停止标记。结束后不自动开启环境光。

用户只需观察自己的头发和周围 NPC 头发哪些部分变紫，有条件时保留一张截图。先确认可见覆盖，再决定是否需要定位其他头发变体或皮肤/衣服的独立入口，不重复要求换地图寻找细微差异。

状态文件仍为 `SMSM-native-captures/ambient-status.json`：`enabled` 只表示环境光实验；`coverage_enabled` 表示标记，`coverage_draws`/`coverage_fallbacks` 仅为 CPU 绘制计数，不是可见像素数量。

## 验证与部署

12 项离线原始材质实际绘制/签名检查通过，包括透明混合、alpha/discard、深度取样拒绝及混合区域。WARP 桥验证真实标记像素、默认关闭、无需环境数据、十秒截止、手动关闭和异常恢复。官方 ReShade 硬件 host 验证覆盖命令、无全屏来源时的三次替换、真实十秒到期状态回写及手动停止；该 host 使用零顶点，只证明回调连接，不代表游戏可见覆盖。环境光 shader 字节码沿用已验证的 r4，未改光照系数。升级/中断恢复/旧版恢复及命令能力与重复请求拒绝在模拟客户端验证。

摘要：[r5 验证](validation/native-coverage-r5-2026-10-09.json)。游戏实机覆盖尚待短测试，完整 M2、画质收益和 GPU 成本未通过。安装遵循停机更新和独立备份，保留 r4、r3 和 r10；r5 是诊断候选编号，不是新的正式 release。

## 实机负结果与真实像素补测

后续游戏已启动；首次十秒标记及用户要求的持续续开均未观察到紫色。用户提供画面截图，玩家及可见 NPC 的头发没有明显标记。续开助手报告 holding、22 次续开；读到状态时覆盖模式开启、累计 83,940 次替换、零 CPU 回退，环境光关闭。停止续开后确认 `coverage_enabled=false`，最终计数 86,922。截图与状态并非同帧同步证据；CPU 计数仍不能证明有效像素或最终画面覆盖。此轮覆盖验收失败，不能据此确认具体是哪一个 GPU 阶段阻止标记。

为排除仅验证零顶点回调的盲点，新增 `tools/test_native_reshade_pixels.py`。复用原始精确头发 PS、同一已安装 r5 DLL 及官方 ReShade，在隐藏硬件窗口中以完整合成材质输入绘制三顶点平面，执行关闭/标记/关闭，并读回实际 RGBA32F 输出：标记帧与紫色期望误差为 0，关闭后与原帧误差为 0，硬件原帧与 WARP 基线最大误差约 2.98e-8。它证明该 runtime 下替换链能改变非零像素，仍不代表游戏状态下有可见覆盖。测试摘要见 [硬件像素验证](validation/native-coverage-pixels-2026-10-09.json)。

下一缺口是游戏中目标绘制的实际输出：需要有界记录 RTV/写入掩码、混合、深度/模板/裁剪状态，并核对目标绘制后的颜色及后续覆盖。历史日志只有状态对象引用，无法还原这些描述；原快照只有 pre-draw 输入，不包含目标的前后颜色证据。不能从“没有紫色”直接断言它只绘制 NPC、使用了另一发型变体或被特定 pass 覆盖。当前所有效果关闭，不再要求用户重复肉眼找差异。
